El prompt la usa como referencia para normalizar el nombre del banco (ej. "BAC" -> "BAC Credomatic"), dejando claro que no es una lista cerrada: si el comprobante muestra un banco que no esta en la lista, igual lo transcribe tal como aparece.
- **Bug de validacion de duplicados por texto libre en "banco"**: si el banco quedaba como texto libre, dos lecturas/digitaciones del mismo banco con distinta redaccion (ej. "BANPAIS" vs "Banco del Pais") no se detectaban como el mismo banco y la validacion de duplicados fallaba. Se cambio el campo "Banco" del modal (`ventas_comprobantes_pago.php`) de texto libre a un `<select>` con el catalogo fijo de `ia_comprobantes_lista_bancos_hn()` (mismas opciones que usa el prompt de la IA) mas una opcion "Otro (especificar)" que revela un input de texto solo para bancos fuera del catalogo. El valor que realmente se guarda (campo hidden `banco`) siempre es el texto exacto de la opcion elegida del catalogo -letra por letra igual cada vez-, o el texto escrito a mano solo cuando se elige "Otro". La IA sigue proponiendo el banco automaticamente: si coincide con el catalogo se preselecciona esa opcion; si no, cae en "Otro" con el texto leido precargado para que el usuario lo revise.
- Se agrego "Financiera COFISA" al catalogo `ia_comprobantes_lista_bancos_hn()`.
- **Los campos que la IA logra leer del comprobante ya no se pueden modificar en el modal** (banco, fecha, referencia y monto quedan en solo lectura cuando la IA los extrajo con exito), para que no se pueda alterar lo que realmente dice el documento antes de guardarlo. Solo quedan editables los campos que la IA no pudo leer (o todos, cuando no hay API key configurada / la lectura automatica no esta disponible). Implementado en `ventas_comprobantes_pago.php` con `comprobante_bloquear_extraidos()` / `comprobante_desbloquear_todo()`; se agrego una nota visible en el modal explicando el bloqueo.
- **Verificacion anti-manipulacion en el servidor**: el "readonly" del modal es solo una ayuda visual (se puede saltar con las herramientas de desarrollador del navegador o mandando la peticion directo). Se agrego `verificar_comprobante_no_modificado()` en `include/ia_comprobantes.php`: al guardar (`guardar_comprobante` en `ventas_comprobantes_pago.php`), el servidor vuelve a leer el archivo real con la IA y compara contra lo que se esta guardando; si para algun campo que la IA logra leer el valor no coincide (banco/fecha/referencia/monto), se rechaza el guardado con "No se pueden modificar los datos que la IA extrajo del comprobante." Se agrego `temperature: 0` a la llamada de la IA (`ia_comprobantes_llamar_api`) para que la relectura sea lo mas consistente posible con la lectura original. Probado: acepta datos correctos, rechaza monto y referencia alterados.
